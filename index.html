My writing principles

The rules I edit by. Each one links to a place in my samples where you can see it at work.

  • If I didn’t test it, I don’t publish it.

    I run every step and command myself, and reproduce reported errors, before content reaches a learner.

    $ terraform validate Success! The configuration is valid.
    See what I tested in the Terraform lab

  • One step, one action.

    Explanations go in notes, so readers can scan the steps to see what to do and read the notes to learn why.

    9Click Create deployment.
    Note: A Success notification confirms the deployment was created.
    See it in the AWS lab edit

  • Name the control, not just the label.

    “Choose the Aliases tab” is faster to follow than “Choose Aliases.” Readers find what they know to look for.

    CodeTestAliasesVersions
    Choose the Aliases tab.
    See it in the AWS lab edit

  • Write for the person who’s stuck.

    People open documentation in the middle of a problem. Every page should help them recover, including when something goes wrong.

    Connection closedReturn to CloudShell and repeat the SSH steps to reconnect.
    See it in the AWS lab edit

  • Feedback should say what to fix.

    Review comments for authors are specific, kind, and actionable, so a revision takes one pass instead of three.

    JBGreat flow here. Can we name the exact menu so learners don’t have to search for it?
    See it in the AI lab review
